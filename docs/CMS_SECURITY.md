# 後台資安與備份手冊

## 管理員登入

管理員必須完成帳密與第二步驗證才會收到後台登入狀態。驗證器使用 TOTP，允許前後一個 30 秒時段以容納少量時鐘誤差。同一驗證碼時段成功後不得再用。登入挑戰在五分鐘後或連續五次錯誤後失效。

復原碼各只能使用一次。更換裝置前請在驗證器 App 備份或移轉帳號。若驗證器與復原碼均遺失，由主機管理者停機處理，先備份資料並確認管理員身分，再離線移除 `accounts.json` 中固定 `admin` 帳號的 `mfa` 欄位。重啟後以現有密碼重新綁定驗證器。此流程不提供公開 API。

## 內容備份與還原

1. 在後台的「備份與操作紀錄」建立備份，確認新備份已列出。
2. 需要還原時選擇備份並確認。系統會先做一份保護備份，保留還原前的狀態。
3. 確認前台、草稿預覽、相片及最近操作紀錄。還原會增加版本號，其他已開啟的舊版編輯頁會收到衝突提示。

這類備份在 `backups/`，保存草稿、已發布內容、上一版及站上傳圖片。還原會保留目前的管理員驗證、帳號權限及稽核紀錄。備份與圖片保存在同一個磁碟，須另外保留站外副本以應對磁碟故障。定期檢查磁碟用量。

## 整站災難復原

停機後備份完整的 `DEMI_DATA_DIR`。正式主機可搭配每日磁碟快照，再定期保存加密的站外副本。帳號資料含密碼雜湊和驗證器機密，必須只向授權的主機管理者開放。請在獨立測試目錄試做還原，再將服務指向選定的已還原目錄。登入狀態在重新啟動後需要重新建立。

在正式環境使用 HTTPS，限制資料目錄僅服務帳戶存取，並避免把內容、帳號、驗證器金鑰、備份或測試帳密加進 Git。

## 權限與發布紀錄

管理員可在後台查看最新 100 筆記錄。完整記錄位於 `audit.jsonl`。權限變更包含操作者、目標帳號、變更前後權限、是否停用及是否重設密碼。發布、回復與備份記錄包含操作者、時間和版本或備份識別。紀錄只由應用程式追加，主機管理者仍有檔案存取權。
